# Почему блок thinking пустой и что с этим делать

Проверено 30 октября 2026. Основание: официальная документация Anthropic, независимый криптоанализ,
исходники Retool и живые прогоны против текущего аккаунта. Документ фиксирует результат; ниже
явно разделены «доказано», «не удалось» и «решено кодом».

## Симптом

Opus 5.5 (и вся линейка 5/5.5) отдаёт блок `thinking` с **пустым текстом** и подписью. На сложной
задаче при `effort=max`: 109 с, подпись **34 028 байт**. Текста нет ни на direct-транспорте
(`copilotStreamGPT`), ни на WebSocket, ни в сохранённой истории треда.

## Причина — это документированное поведение провайдера

`thinking.display` — поле объекта `thinking` в Messages API; допустимые GA-значения
`"summarized"` и `"omitted"` (плюс бета `"updates"`). У `"omitted"` thinking-блок возвращается
с пустым `thinking` и полной подписью.

**`"omitted"` — значение по умолчанию на Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5, Opus 4.8 и 4.7**
(и на Fable/Mythos/Haiku 5.5). `"summarized"` — дефолт только на Opus 4.6, Sonnet 4.6 и старше.
Опт-ин: `thinking: {"type": "adaptive", "display": "summarized"}`.

- https://platform.claude.com/docs/en/build-with-claude/thinking#controlling-thinking-display
- ровно наш симптом: https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting#the-thinking-field-is-empty-in-the-response

Это объясняет матрицу целиком: текст есть там, где `summarized` — дефолт (4.6/Sonnet 4.6), и
пропадает на всех 4.7+/5.x. Ни effort, ни tools, ни реплей блоков на это не влияют.

Не связано ни с ZDR (thinking ZDR-eligible), ни с правами, ни с retention.

## Что перекрывает опт-ин в этом стеке

`copilotStreamGPT` **не принимает `thinking` в теле запроса**. Доказано поведением валидатора:
`reasoningEffort: bogus` → 422, а `thinking: {type: bogus}` и `thinking.display: bogus` → 200,
то есть поле просто игнорируется. Отвергнуты все каналы: `thinking`, `output_config`,
`thinkingDisplay`, `reasoningSummary`, `includeThinking`, `providerOptions`/`providerMetadata`
(стиль AI SDK), `verbosity`, `metadata.*`, `wireModel` (принимается, но не действует).

Дополнительно Retool **вырезает блоки thinking из истории**: маркер, положенный в `thinking`
ассистентского сообщения, до модели не доходит. Поэтому и «инъекция зашифрованного размышления»
(перенос подписи в более слабую модель) внутри Retool сейчас невозможна.

## Ретроактивно текст не достаётся

- Реплей не помогает: текст, положенный в `thinking` возвращаемого блока, игнорируется.
- Отдельного эндпоинта «summary по подписи» нет: сводка генерируется в момент инференса.
- Подпись — аутентифицированный шифротекст (AEAD), не декодируется; независимый разбор:
  https://blog.cryptographyengineering.com/2026/05/29/fooling-around-with-encrypted-reasoning-blobs/
  (там же — атака переносом блобов: https://stolen-thoughts.com/).
- Полный, не сокращённый CoT — только по коммерческому соглашению с Anthropic.

## Костыль, который пока убран

Модели, у которых провайдер прячет рассуждение, **проговаривают его сами, если попросить в
пользовательской реплике**. Проверено, что работает и что нет у Opus 5.5:

| способ просьбы | результат |
| --- | --- |
| инструкция уровнем выше (system) | игнорируется, текст не появляется |
| XML-теги `<thinking>`, `<r>` | пустой ход (0 символов) |
| заголовок в скобках `[REASONING]` в конце реплики | пустой ход (3/3) |
| «покажи шаги» + разделитель `---` | устойчиво работает (3/3) |

Отсюда форма директивы: без скобочного заголовка и без XML.

Флаг был `thinking_reveal` (реализован, проверен, затем снят — в коде relay его сейчас нет):

| значение | смысл |
| --- | --- |
| `off` | по умолчанию, поведение не меняется |
| `auto` | только для моделей с флагом `thinking_hidden` |
| `always` | для всех моделей |

При включении relay дописывает директиву, буферизует ответ до строки `---` и уводит часть до неё
в события `thinking`, а остаток — в текст. Если модель директиву проигнорировала, буфер
выпускается обычным текстом, ответ не теряется. Ограничения: только ходы без клиентских
инструментов (иначе конфликт с подавлением `<tool_call>`), и это пересказ моделью, а не
провайдерская сводка.

Снят по решению владельца: пересказ — не провайдерский текст. Код возвращён к исходному
состоянию, поведение проверено: у Opus 5.5 в thinking снова только метка-заглушка, у моделей
с открытым рассуждением — их настоящий текст.

## Не удалось

- Заставить Retool отправить `display: "summarized"` клиентским полем.
- Бета-заголовки (`thinking-display-updates-2026-08-18`, `thinking-binding-controls-2026-08-01`)
  тоже недоступны: relay не управляет заголовками запроса Retool.
- Маркер эндпоинта `/api/gpt/queryGPT` (отвечает 400 «The request does not come from Retool client»).
