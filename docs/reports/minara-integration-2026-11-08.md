# Minara: интеграция и проверка 8 ноября 2026 года

## Задача и результат

Добавлен второй upstream Minara с Bearer-авторизацией, отдельно от Retool.
Поддержаны конфигурации только Minara и смешанный пул. HTTP-запрос использует
`curl_cffi` с `impersonate="chrome131"`, `stream=True`, без перенаправлений.
Маршрут клиента `minara/<полный upstream ID>` не пересекается с Retool-моделью
и не переключается на неё при неизвестном ID. Настройка описана в
[руководстве Minara](../minara.md).

Пользователь разрешил небольшие платные проверки на предоставленном тестовом
аккаунте. Токен не включён в исходники, примеры, этот отчёт или Git. Проверки
проводились отдельными процессами relay на случайном loopback-порту, с временными
конфигурацией и состоянием. Рабочий relay и его `config.json` не заменялись и не
перезапускались.

## Этапы работы

1. До реализации изучены текущий код и PR #24, его последующий стек #25–55,
   транспортные гарантии #18/#19/#21. Локальный исходник уже включал более новые
   изменения, чем удалённый head PR #24; откат к старой архитектуре не выполнялся.
2. Разработчики разделили транспорт, маршрутизацию/конфигурацию и документацию.
3. Отдельные проверяющие исследовали реализацию, после чего агенты пытались
   сломать отмену, payload, конфигурацию, учёт и клиентские продолжения.
4. Подтверждённые находки переданы проверяющим и исправителям. После исправлений
   проведены повторные независимые проверки, смешанные HTTP-прогоны, проверки
   реальных установленных клиентов и заключительные live-запросы.

Самопроверки автора scoped-каталога не выдавались за независимое ревью этого
изменения. Независимые воспроизведения и проверки транспорта/usage выполнялись
другими участниками. Итоговая интеграция и коммит остаются ответственностью
основного агента.

## Закрытые находки

| Область | Подтверждённая проблема | Исправление и доказательство |
|---|---|---|
| Адрес и секреты | `RETOOL_BASE` мог изменить адрес Minara-only запроса с Bearer | Retool-переменные не применяются к Minara; регрессия проверяет фактический URL и заголовок исходящего запроса |
| Конфигурация | Необработанный malformed URL, неверные порты, управляющие символы | Контролируемая валидация URL, токена и label до сохранения; HTTP admin возвращает 4xx без изменения файла |
| Каталог | Конфликт описаний одной модели сохранял незапускаемую конфигурацию | Чистая проверка совокупного каталога до записи; конфликт отклоняется |
| Каталог | ID с `:high` не проходил обратный разбор | Полный настроенный ID имеет приоритет; профили и `#effort` проверены |
| Каталог | Загрузка другой конфигурации меняла уже работающий Runtime | Каталог принадлежит конфигурации; два живых Runtime сохраняют независимые ID и capabilities, включая одинаковый ID с разными tools |
| Возможности | `tools: false` не запрещал tool-запрос | Ранняя 422-проверка для Chat, Responses и Messages |
| Отмена | `Response.close()` блокировал общий event loop | Сигнал отмены и отдельная очистка; реальный loopback curl-тест проверяет heartbeat и отмену до завершения чтения |
| Ресурсы | Отменённые запросы до заголовков могли продолжать занимать физические workers | Бюджет физических запросов удерживается до завершения worker/cleanup; истёкший admission не создаёт POST |
| Ошибки | Curl timeout становился 502 | Санитизированный 504 без раскрытия текста исключения и без автоматического платного повтора |
| Продолжения | Каноническая история скрывала результат relay exec | Generated followup используется после exec; настоящий безопасный subprocess и второй запрос проверены во всех трёх диалектах |
| Фильтрация | Пустой `content_filter` становился empty-turn ошибкой | Терминальный отказ сохраняется и не запускает exec/server-search/повтор; проверены stream и non-stream |
| Протокол | Конфликтующие finish reasons могли изменить отказ на успех | Контролируемая 502; совпадающий повтор finish в usage остаётся допустимым |
| Протокол | Глубокий JSON и escaped surrogate давали внутренние ошибки | Ограничение глубины и проверка Unicode; валидные astral-символы сохраняются |
| Изображения | Image tool-result сериализовался как JSON-текст | Tool ID остаётся связанным; visual input передаётся последующим user image block после всех параллельных tool-result |
| Учёт | Cached input считался дважды, стоимость терялась или называлась кредитами Retool | Канонические token counters, отдельные `provider_cost` и валюта только при наличии; неизвестные значения остаются неизвестными |
| Учёт | Попытка считалась до фактического POST; lifetime-детали росли | Учёт на границе отправки, ограниченные последние записи и отдельные lifetime-счётчики; admission timeout — ноль попыток |
| Учёт | Overflow и исправление snapshot давали невалидное/неверное число | Строгий JSON, null/overflow и консервативно неизвестная сумма вместо неверной; валютные группы учитывают реальные нулевые записи |
| Admin | Pending Bearer не маскировался в free-text label/journal | Новый секрет включается в redaction до события и в чтение pending записей; намеренное поле токена на диске сохраняется |

## Автоматические проверки

Полный локальный прогон Python 3.14:

```powershell
uv run --python 3.14 --with-requirements requirements.txt --no-project python -m pytest -n 4 -o addopts= -q --tb=short
```

Наблюдённый результат заключительного лога: **9950 passed, 2 skipped, 3 warnings**,
68,66 с. Среди предупреждений — тест искусственно сломанного console writer и
`curl_cffi`, сообщающий, что `chunk_size` игнорируется. Это не заявление о CI или
прогоне на другой ОС. Более ранние результаты 9802/9924 относятся к предыдущим
состояниям исходников, а не заменяют заключительный прогон.

Независимые заключительные команды:

```powershell
uv run --python 3.14 --with-requirements requirements.txt --no-project python -m pytest -o addopts= -q tests/test_minara_transport.py tests/test_minara_filter.py tests/test_minara_mixed_clients.py --tb=short
uv run --python 3.14 --with-requirements requirements.txt --no-project python -m pytest -o addopts= -q tests/test_minara_usage.py --tb=short
python -m pytest tests/test_minara_catalog_scope.py tests/test_minara_integration.py tests/test_prompt_models_parse.py tests/test_minara_mixed_clients.py tests/test_minara_admin.py tests/test_minara_filter.py -q --tb=short
```

Результаты: соответственно **107 passed** с одним известным curl warning,
**29 passed**, **293 passed**. Отдельная проверка exec/server-search дала 4 passed;
реальное закрытие и создание нового Runtime с дисковым состоянием — 3 passed,
по одному на каждый диалект. Restart-тест не выдаётся за OS kill между файловыми
операциями: он закрывает и создаёт Runtime/store заново в одном pytest-процессе.

Админка: заключительный браузерный лог содержит **11 passed**, включая Minara
Bearer-форму, обе темы/узкий экран и отсутствие смешения денежных единиц. Команда
`npm run test:design` в `web/` дала **132/132 checks passed**. Это выбранные
браузерные сценарии и существующий design gate, не доказательство всех возможных
пользовательских действий.

## Установленные клиенты

Реальные бинарники использовали изолированный relay и **синтетический upstream**,
а не платную Minara-генерацию:

| Клиент | Проверенный результат |
|---|---|
| Codex 0.167.0 | Responses text; фактический `view_image` валидного PNG и строго проверенная передача visual tool-result; финальный ответ |
| Claude Code 2.1.310 | Messages, настоящий read-only `Read`, результат файла во втором payload, финальный ответ |
| OpenCode 1.19.3 | Chat, настоящий read-only `read`, результат файла в продолжении, финальный ответ; отдельный service request |
| DeepSeek Harness 0.2.2-alpha.3 | Изолированный headless профиль, настоящий `read`, tool-result и финальный ответ; отдельная title-генерация |

Codex проверен с `web_search="disabled"`: его default server `web_search` не
поддерживается этим relay-контрактом и получает 422. Это **не** успешная проверка
настроек Codex по умолчанию. Его попытка shell-чтения была отклонена политикой
host; обход не выполнялся. Успешная проверка tool-result использовала разрешённый
`view_image`. Все профили, ключи и scratch-файлы этих запусков были временными;
глобальные настройки клиентов не менялись.

## Заключительные платные проверки Minara

На текущем коде сначала проведены восемь небольших generation POST к
`openai/gpt-oss-20b`, `max_tokens=512`:

| Сценарий | Наблюдение |
|---|---|
| Chat non-stream / stream | HTTP 200, `OK`, stop / stop + DONE |
| Responses non-stream / stream | HTTP 200, `OK`, completed / response.completed + DONE |
| Messages non-stream / stream | HTTP 200, `OK`, end_turn / message_stop + DONE |
| Forced `echo(word)` | HTTP 200, аргумент `OK`, tool_calls |
| Продолжение с результатом `echo` | HTTP 200, текст `OK`, stop |

Отдельный relay показал `/health` 200 с `balance_known: false`; `/v1/balance`
вернул 503 с неизвестными остатком и единицей — документированное отсутствие
balance endpoint, а не отказ генерации. Все восемь ответов содержали отдельную
стоимость upstream, полноту стоимости и неизвестную валюту; `credits_used` остался
null. Стоимости с неизвестной валютой не суммируются как деньги и не называются USD.
В этой матрице cache counters были нулевыми.

Затем установленный Claude Code 2.1.310 подключён к **живой Minara** через
отдельный relay: `--bare`, только разрешённый `Read`, без сохранения сессии,
с пустым MCP-конфигом и временным каталогом настроек. При effort low и output
cap 1024 модель прочитала временный файл с уникальной строкой и вернула её после
tool-result. Наблюдены два Messages POST с HTTP 200, `num_turns: 2`, terminal
completed, `is_error: false`, без permission denials. Это настоящий установленный
клиент → relay → Minara → Read → tool-result → ответ, а не synthetic upstream.

Клиент сообщил cache-read usage; исходные upstream usage snapshots этих двух
попыток не сохранялись, поэтому независимая проверка арифметики cache hit остаётся
офлайн. Денежная оценка самого Claude имеет неизвестный cost basis и не выдаётся
за выставленный Minara расход или подтверждённую валюту. Она не прибавляется к
стоимостям предыдущей матрицы. Итого заключительная live-приёмка — **10 платных
POST**: восемь HTTP-сценариев и два хода установленного Claude. Проверен low,
но не все объявленные в тестовой конфигурации effort-уровни.

## Границы доказательств

- Проверена названная Minara-модель, а не весь каталог. Возможности других моделей,
  vision на живой Minara и все effort-уровни не утверждаются.
- Установленные client tool smoke и live API matrix — разные проверки; одна не
  заменяет другую. Дополнительно live tool-use подтверждён для Claude Code;
  успех синтетического tool-result остальных клиентов не доказывает их live tool-use.
- Фоновые Minara refresh, balance fetch и keepwarm отключены; нет обещания
  автоматического продления Bearer или проверки действительности токена через health.
- Тесты не доказывают отсутствие всех ошибок. Отчёт фиксирует наблюдённые проверки
  и исправленные воспроизведения на эту дату. Секреты и частные wire captures
  сознательно не опубликованы; экспериментальные скрипты оставлены вне Git.
