# Скорость запросов и время консольных строк — 8 ноября 2026

## Что добавлено

- В «Активности / Ходы моделей» у каждого завершённого запроса — скорость в ток/с, включая мобильную раскладку.
- В «Сводке» — отдельная средняя скорость за выбранное окно и число измерений.
- Консольные строки relay и супервизора получают локальную дату, время с миллисекундами и UTC offset.

Формула: сообщённые upstream выходные токены всех попыток / секунды обработки запроса до завершения runner.
Включены очередь max_workers, разбор тела, ожидание сессии, мышление, повторы, смена аккаунта, поиск и команды.
Передача последних байтов клиенту после runner исключена. Это не чистая скорость декодирования и не оценка
числа токенов по длине текста. Старые/неполные данные — прочерк; подтверждённый ноль остаётся нулём.

Средняя — отношение сумм токенов и времени, не арифметическое среднее скоростей. В неё входят только
успешные stop/tool_calls с полными данными. Обрезка length может иметь индивидуальную скорость, но в среднюю
не входит. Замер request.speed один на клиентский запрос, прикреплён к последнему account-turn. Его
request_duration_ms в API traces не следует путать с duration_ms отдельного account-turn.

## Выполненные независимые стадии

1. Три исполнителя: backend, frontend, консольное время.
2. Другие агенты проверили каждый участок.
3. Отдельные adversarial-агенты пытались сломать расчёты и вывод.
4. Независимый verifier воспроизвёл находки, отделив доказанные проблемы от гипотез.
5. Два новых fixer-агента исправили подтверждённые проблемы.
6. Ещё один агент проверил исправления; родитель проверил интеграцию, тесты и итоговый diff.

Во время этих стадий найдены и исправлены:
- смешение wall-clock и monotonic в session.acquire;
- завышение скорости при failover: считался только последний успешный аккаунт;
- возможность подделать время многострочного сообщения timestamp-подобным payload;
- два error-path без времени: explain fetch и ротация журнала.

Ротация пишет безопасный класс исключения в stderr через независимый console_clock, не рекурсируя в журнал.
Обычные сообщения всегда получают настоящее время; только явный replay сохраняет исходные timestamps.
Просмотр старых строк без даты не выдумывает дату события.

## Регрессии и ограничения

Тесты покрывают weighted average, unknown/zero, повторные snapshots, retries, real two-account failover,
сохранение раннего unknown перед quota, реальный HTTP slot wait, восстановление журнала, timestamps,
redaction до разбиения строк, поддельную дату, stderr и broken pipe. Синтетический failover раньше давал
скорость примерно в 11,6 раза выше request-wide; теперь его длительность учитывается целиком.

Live-запросы к Retool и перезапуск рабочего relay не выполнялись. Проверки используют fixtures.
Для появления новых измерений и консольных timestamps нужен запуск обновлённого backend; исторические
записи не пересчитываются задним числом. Админка со старым backend показывает отсутствие данных.
