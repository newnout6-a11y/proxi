## 4. Живая папка обновлена, relay не перезапущен

Relay работает из `C:\specialinay_papka` с ветки `codex/model-client-audit`, куда стек собирается коммитами вида
«live: …». Я сделал так же: все коммиты лежат в PR (ветка `split/32-project-tidy` поверх `split/30-performance`), а в
живую папку перенесены одним коммитом «live: …» (`c4cad9b`). PR: https://github.com/newnout6-a11y/proxi/pull/55. Отчёт о том, что исправлено и где, — `docs/reports/fixes-2026-11-07.md`. Два отчёта, которые лежали в `docs/` вне Git, теперь в `docs/reports/`, а их исходные копии — в `C:\specialinay_papka_archive\2026-11-07\docs\`.

**Relay я не перезапускал**: он обслуживает и эту сессию. Запущенный процесс работает на старом коде, новый
заработает после перезапуска. Сразу обновилась только админка (её файлы `web/dist` отдаются с диска): если вкладка
админки открыта, обновите её. Новая админка со старым relay совместима.

Что изменится после перезапуска и может удивить:

- **git через локальные команды relay** (`exec_policy: allowlist`) — только чтение и `fetch` из настроенного remote по
  имени; `push`, `commit`, `checkout`, `reset`, `clean` требуют `exec_policy: allow_all`. В командах PowerShell `;` вне
  кавычек и перевод строки отклоняются: несколько команд соединяйте через `&&`, а операторы PowerShell держите внутри
  тела в кавычках. Клиентов со своими инструментами (Claude Code, Codex, OpenCode) это не касается: relay exec у них не
  используется.
- **Картинки по ссылке** идут через системный прокси, если он задан.
- **Супервизор `scripts/run_relay.ps1`** не запускает relay, если порт уже занят (раньше перезапускал его каждые 2 с
  вечно), и останавливается после 8 неудачных стартов подряд; причина — в `relay.log`. `relay.log` ротируется на
  20 МиБ (`relay.log.1`…`.3`).
- **Стартовый баннер** показывает ключ relay как «(set, N characters)», у длинного ключа — первые и последние 4 символа.
- **Неверный ключ с 127.0.0.1** — всегда 401, без счётчика попыток (см. пункт 5.5).
- **Простаивающие диалоги** уходят из пула через `conversation_idle_timeout` (900 с), как и обещал README, а не при
  следующем запросе.

Если после перезапуска что-то пошло не так, вернуть живую папку к прежнему коду можно одной командой (relay перед этим
остановите; команда добавит коммит, который отменяет «live: …», история не теряется):

```bash
git -C C:/specialinay_papka revert --no-edit HEAD
```

## 5. Решения от 8 ноября — сделано

Мы разобрали вопросы вместе. Всё ниже сделано, проверено тестами и уже лежит в PR #55 и в живой папке. Подробности —
в `docs/reports/fixes-2026-11-07.md`, пункты 69–82.

1. **`git push` через relay exec** — убран; `git fetch` только из настроенного remote по имени (`git fetch origin`).
   Если когда-нибудь понадобится `push` или `commit` через локальные команды relay, нужен `exec_policy: allow_all`.
2. **Короткий ключ relay** — при старте relay предупреждает, если ключ короче 32 символов.
3. **Картинки по ссылке** — если в системе задан прокси, качаются через него; без прокси соединение идёт ровно на
   проверенный адрес. Таймауты прежние, 10 с.
4. **Regex-правки** — результат правки запоминается для текста (ничему не «учится», просто не пересчитывает), а
   шаблоны вида `[ \t]+$` ускорены (20 тыс. пробелов: 1,5 с → 0,001 с).
5. **Пауза журнала** — замораживает только список событий; ходы и значок ошибок живут.
6. **Ветки** — удалены 27 веток, целиком вошедших в стек. Рабочие копии не трогал.
7. **Недоделки** — сделаны (а) восстановление ждёт запись из очереди и (г) выход не ждёт поиск и баланс. (б) и (в)
