# Продолжение ночной работы Proxi

Проверяются исходные пункты R2–R6 и новый R7. Для живой проверки сначала нужен
успешный прогон на поддельном upstream, затем отдельный временный relay и короткие
запросы с ограниченным выводом. Записываются коммит, клиент, модель, тип запроса,
время до первого текста и итог. Если доступных настроек для конкретного транспорта
нет, строка матрицы остаётся непроверенной.

Начальный живой контроль для R1: Chat Completions через Minara ответил 200,
первый текст пришёл за 1545 мс. Это подтверждает рабочий путь тестового relay,
но пока не закрывает матрицу остальных форматов или IDE.

## R2: завершение SSE

Сверены документированные признаки конца: [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)
использует `finish_reason` и маркер `[DONE]`; [Responses](https://developers.openai.com/api/reference/resources/responses/streaming-events)
использует именованные события результата; [Anthropic Messages](https://platform.claude.com/docs/en/build-with-claude/streaming)
заканчивается `message_stop`. На синтетическом upstream каждый из трёх драйверов
ранее выдавал 200 после обрыва. После исправления такой поток возвращает ошибку,
не записывает частичный ответ в историю и не выдаёт накопленный вызов инструмента.

| Живой путь клиента через Minara | HTTP | До первого текста | Всего | Конец |
|---|---:|---:|---:|---|
| Responses | 200 | 1835 мс | 1837 мс | `response.completed` |
| Anthropic Messages | 200 | 1331 мс | 1332 мс | `message_stop` |

Оба запроса к `minara/deepseek-v4-flash` дали ожидаемый ответ. По журналу они
израсходовали 0,003 кредита Minara. Это живые проверки преобразования клиентских
протоколов, а исправление прямых универсальных драйверов подтверждено на заглушках.
На Python 3.14 прошли 70 целевых тестов протоколов и маршрутизации и полный набор:
11 023 прошли, 2 пропущены. Ruff и `git diff --check` прошли.

## R3: таймауты Minara и быстрые кандидаты

`504` и `524` от шлюза Minara превращаются в `upstream_timeout`, а оригинальный
HTTP-статус сохраняется в диагностике. У обрыва может быть списание, поэтому
relay не повторяет генерацию после этих статусов, пустого 503 или SSE-ошибки.
Релею всё ещё разрешено повторить явно распознанный отказ выбора канала; тест
подтверждает закрытие старого ответа и получение результата на следующей попытке.
Синтетический тест с двумя аккаунтами проверяет отсутствие второй отправки на 524.
Живой 524 намеренно не вызывался: его наличие уже видно в прежних трассах.

Контрольный живой запрос: одна и та же короткая арифметическая задача, отдельный
контекст каждого запроса, лимит 64 токена, один аккаунт Minara. Три результата верны.

| Модель | Effort | HTTP | До первого текста | Всего |
|---|---|---:|---:|---:|
| `minara/gpt-6-luna-pro` | low | 200 | 4440 мс | 4441 мс |
| `minara/glm-5.3-flash` | minimal | 200 | 2344 мс | 2347 мс |
| `minara/deepseek-v4-flash` | none | 200 | 1224 мс | 1227 мс |

Журнал суммарно показал 0,0459 кредита Minara. Flash-кандидаты подходят для следующей
проверки коротких служебных ответов. По одному примеру нельзя оценить качество
резюме или память длинной сессии. Рабочие маршруты не менялись; `gpt-5.4-mini`
не включён в эту сопоставимую проверку.
Проверки: 234 целевых теста и отдельная матрица с двумя аккаунтами, полный набор
на Python 3.14 — 11 029 прошли, 2 пропущены. Ruff и `git diff --check` прошли.

| Пункт | Ближайшая проверка |
|---|---|
| R2 | Отдельно подтвердить исходные форматы OpenAI Chat/Responses, Anthropic Messages и Minara. Различать корректное завершение, обрыв и тишину; keepalive считать транспортным событием. |
| R3 | Измерить короткие задачи и стабильность быстрых кандидатов. Ошибку Minara 524 классифицировать отдельно; при неоднозначном завершении платный запрос автоматически не повторять. |

## R7: первичная сверка

Retool [документирует](https://docs.retool.com/org-users/guides/retool-api/authentication)
Bearer-токены организации с явными правами для [API v2](https://docs.retool.com/org-users/concepts/retool-api).
Документация по [Retool AI](https://docs.retool.com/data-sources/reference/ai-models)
отдельно описывает модели для AI-ресурсов и агентов. Это не подтверждает, что Bearer-токен
API v2 подходит для текущего пути Copilot в relay. В исходниках текущего пути есть
версия веб-клиента и поле `requestOrigin: Browser`; они относятся к другому протоколу.
Для запуска заранее настроенного Workflow Retool [документирует отдельный ключ](https://docs.retool.com/workflows/guides/webhooks)
в заголовке `X-Workflow-Api-Key`. Штатный вариант для автономной интеграции — отдельный
Workflow с нужным AI-действием, ограниченный ключ и явные пределы запросов; у него
свой жизненный цикл и он не гарантирует паритет с Copilot. На этой машине подходящий
Workflow не запускался. Изменения идентификации и обход ограничений провайдера в
проверку не входят.

## Открытые вопросы и ограничения

- В прежней сторонней трассе остался текущий ключ relay. Ротация потребует синхронно
  обновить клиентские профили. Действительность старых сессий Retool из публичной истории
  не установлена. Эти операции не привязаны к проверке свежего кода.
- Для живой матрицы независимых провайдеров нужны их штатные тестовые учётные данные.
  При исходной сверке список универсальных провайдеров был пуст; публичный каталог
  и успешный ответ другого транспорта не засчитываются как живой прогон.
