## 3. Исправленные ошибки

Формат: **где** — что было не так и как это проявлялось → что изменено. Тест — файл в `tests/`.

### Безопасность

1. **`executor.py`, `_check_segments` и список `CMD_LETS`** — allowlist команд по умолчанию позволял модели запустить
   любую программу на компьютере. Достаточно, чтобы в текст, который модель читает, попала подходящая инструкция, при
   клиенте без своих инструментов (curl, скрипт, простой чат). Подтверждено по `check_policy`:
   - `git rebase -x "…"`, `git ls-remote --exec=…`, `git archive --exec=…`, `git clone -u …`,
     `git clone --config core.sshCommand=…`, `git push/fetch-pack/send-pack --exec=…` проходили проверку и запускали
     программу через shell git;
   - в PowerShell `… | ForEach-Object -MemberName InvokeScript …` выполнял любой скрипт, а `ForEach-Object Delete` и
     `ForEach-Object Kill` удаляли файлы и завершали процессы; `$` проверялся только в начале команды.

   → git под allowlist выполняет только команды чтения (`status`, `log`, `diff`, `show`, `blame`, `grep`, `ls-files`…),
   а также `fetch` и `push` без `--exec`; `branch` и `tag` разрешены только для просмотра списка. В PowerShell убран
   `ForEach-Object`, `$` запрещён в любом месте, запрещены провайдеры `variable:`, `env:`, `function:` и реестр.
   Свойства по-прежнему читаются через `Select-Object -ExpandProperty`. Это изменение поведения: `git commit`, `reset`,
   `checkout`, `clean` через локальные команды relay теперь требуют `exec_policy: allow_all`. README и раньше говорил,
   что правки делаются инструментами клиента. Позже верификаторы аудита нашли ещё один обход: git принимает любое
   однозначное сокращение длинной опции, и `fetch --upload=<программа>`, `push --exe=`/`--rece=`, `grep --open=`
   запускали программу → длинная опция, которая может оказаться началом опасной, тоже отклоняется. Тест:
   `test_exec_policy_bypasses.py`.
2. **`validate.py`, проверка адреса картинки по URL** — не отсекала `100.64.0.0/10` (carrier-grade NAT и все адреса
   Tailscale): relay скачивал картинку изнутри tailnet и отдавал её модели → адрес теперь должен быть `is_global`. Тест:
   `test_image_url_guard.py`.
3. **`config.py`, `_load`** — плейсхолдер `"<optional; иначе env RELAY_API_KEY …>"` из `config.example.json`, если
   скопировать пример по README как есть, становился ключом relay. Этот ключ открыто лежит в репозитории, а свой ключ
   не создавался → значение в угловых скобках игнорируется с предупреждением. Живой `config.json` эта ошибка не
   затронула. Тест: `test_config_placeholders.py`.
4. **`auth.py` и `config.py`, `reload_auth` / `merge_set_cookie`** — после первого продления сессии из списка маскируемых
   секретов пропадал ключ веб-поиска (EXA_API_KEY), и он мог уйти в вывод команд и контекст, а имя хоста арендатора,
   наоборот, начинало маскироваться → список пересобирается с ключом поиска (`auth.secret_values`). Тест:
   `test_secrets_after_renewal.py`.
5. **`proxy.py`, `_dispatch`** — если на запрос отвечали, не прочитав его тело (401, 404, 405, выключенный API), тело
   оставалось в keep-alive соединении. Следующий запрос клиента читался вместе с ним и получал 400 или 501 (у Node fetch,
   на котором работают Claude Code и OpenCode, — в 3 из 3 прогонов), а неавторизованное тело-запрос даже выполнялось →
   такое соединение закрывается с `connection: close`. Тест: `test_unread_body_keepalive.py`.
6. **`admin.py`, сохранение настроек** — при `config.json` только для чтения (README это советует) сохранение отвечало
   500 и оставляло рядом полную копию `config.json` со всеми cookies (`.admin-*.tmp`, не в `.gitignore`), по одной на
   каждую попытку → запись идёт через общий `config._write_file`. Тест: `test_admin.py`.
