## Что проверено платными запросами

Сохранённый запрос воспроизводит пустоту. Короткий контроль той же модели
отвечает `OK`. Уменьшение `maxCompletionTokens`, отключение кэша, изменение
ролей и передача истории с нативными tool call/result не устранили сбой.
Удаление старой истории позволяет получить tool call, но история в
исправлении не удаляется. Эти сравнения не устанавливают причину внутри
Retool/Anthropic. Изменение темы запроса также может повлиять на результат.

Просьба сообщить текущий проверенный результат обычным текстом помогла
возобновить генерацию. Одна подсказка оказалась недостаточно надёжной:
встречались пустые и незаконченные ответы. Для восстановительного повтора
с выбором инструментов `auto` дополнительно используется `toolChoice=none`.
После этого на полной исходной истории получены законченные ответы.
Последующее продолжение снова выдало корректный нативный вызов `read`.

## Изменения

- После пустого direct-хода с клиентскими инструментами добавляется просьба
  кратко сообщить результат и следующий шаг. Полная история и system prompt
  сохраняются; модель, effort и определения инструментов не меняются.
- На этом повторе `auto` временно выбирает текст (`toolChoice=none`). Новый
  клиентский запрос начинает с исходного выбора. `required` и конкретное имя
  инструмента сохраняют прежний контракт и не получают такой подмены.
- Thinking/signature без текста или инструмента отмечается `thinking_only`;
  это не успешный содержательный ответ и не повод пропускать backoff.
- Восстановление может продолжаться до исчерпания общего бюджета, максимум
  пять фактических POST, включая первый. Остальные пути расходования бюджета
  и отмена сохраняются.

Статус не выдаётся за выполнение оставшейся работы. После такого ответа
дальнейшая работа инструментов требует следующего клиентского хода.

## Проверка исходного чата

Через API работающего OpenCode отправлено явно обозначенное проверочное
сообщение в ту же сессию, с просьбой прочитать README без изменения файлов.
Чат не пересоздавался и его история не редактировалась.

- `7ac3e310a54f`: корректный нативный `read`, `turn.end=tool_calls`.
- OpenCode выполнил инструмент и вернул его результат.
- `4031681845cb`: законченный ответ с первым заголовком README,
  `turn.end=stop`, сессия OpenCode завершилась как `succeeded`.

После загрузки окончательного варианта кода повторена такая же проверка
в исходной сессии: `39ad35818762` завершился `tool_calls`, OpenCode исполнил
`read`, а `437ce797d568` завершился `stop` с полным правильным заголовком.
Оба запроса ответили с первой попытки; состояние сессии — `succeeded`.
Работающий relay слушает `127.0.0.1:8787`, запущен отдельным скрытым
supervisor через существующий `scripts/run_relay.ps1`.

Модель осталась `claude-opus-5-5`, effort `high`. Внутренняя причина пустоты
у провайдера не установлена. Локальное исправление восстанавливает проверенный
сценарий и сохраняет честную ошибку при исчерпании всех пяти попыток.
