# Структура репозитория и локальные файлы

| Что добавляем | Куда |
|---|---|
| Транспорт и провайдеры, каталог / маршрутизация | `drivers/`, `catalog/` |
| Утилиты сопровождения и интеграции | `scripts/`, клиентские интеграции — `scripts/integrations/` |
| Тесты и фикстуры | `tests/`, интерфейс и его проверки — `web/src/` и `web/tests/` |
| Руководства и описание архитектуры | `docs/` |
| Итоги расследования, аудита или пакета работ, которые нужно сохранить | `docs/reports/`, имя по теме и дате |
| Черновики отчётов агента, временные выгрузки, логи | Вне checkout или в локальной `.tmp/` |
| Бэкапы настоящих конфигов, учетные данные, необработанные дампы запросов | В защищённой локальной папке вне checkout |

Существующие модули Python в корне оставляем на местах. Для нового направления используйте подходящий пакет или выделите небольшой пакет с ясной ответственностью. Для действительно новой точки входа или пакета верхнего уровня добавьте его имя в `ROOT_FILES` или `ROOT_DIRECTORIES` в [проверке](../scripts/check_repo_hygiene.py) и объясните причину в том же изменении. Не расширяйте список ради разового отчёта или артефакта.

```powershell
python scripts/check_repo_hygiene.py
python scripts/check_repo_hygiene.py --worktree
```

Первая команда проверяет пути в индексе Git, включая файлы, добавленные через `git add -f`. Её запускает CI. Вторая проверяет также неотслеживаемые файлы, которые Git не игнорирует. Так можно найти случайный файл до `git add`. В обоих случаях проверяются имена и расположение; команда не открывает файлы и не является сканером секретов. Чтобы проверить, почему локальный файл не виден Git, используйте `git check-ignore -v -- <путь>`.

Чтобы эта же проверка запускалась до локального коммита, в checkout без своих
Git-хуков включите `git config --local core.hooksPath scripts/hooks`. Хук
проверяет индекс и видимые файлы рабочей папки. В новом клоне настройка не
переносится, но проверка индекса в CI работает независимо от неё.

Для обычного запуска укажите `state_dir` в приватном `config.json`, например
абсолютный путь `%LOCALAPPDATA%/Proxi/state` с раскрытым `%LOCALAPPDATA%`.
Журнал, история диалогов и диагностические логи тогда пишутся туда. Для
нескольких экземпляров используйте раздельные профили и каталоги состояния;
`--config` указывает профиль, а `--state-dir` может переопределить его путь.
Ключи и локальные каталоги провайдеров хранятся рядом с конфигом, поэтому
целиком вынесенный приватный профиль лучше помещать вне checkout.

Если проверка нашла файл из другой задачи, не меняйте и не удаляйте его без согласования. Свой черновик переместите в `.tmp/`; для приватного файла выберите папку вне checkout. Если локальный файл уже проиндексирован, уберите его из будущего коммита и проверьте индекс повторно. `.gitignore` не отменяет отслеживание уже добавленного файла. Если действительные учётные данные попали в историю, одного удаления из нового коммита недостаточно: замените скомпрометированные данные и отдельно согласуйте исправление истории.

`web/dist/` — намеренное исключение для выпуска: relay отдаёт готовые файлы, а CI пересобирает их и проверяет совпадение. Lock-файлы зависимостей, например `web/package-lock.json`, тоже хранятся в Git. Фикстурам с искусственными данными давайте отличимые имена (`retool-response.example.json` вместо `config.json`).
