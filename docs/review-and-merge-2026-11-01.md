### 3.1 Безопасность — executor (`executor.py`)
- **Обход allowlist через git → запуск произвольной программы / запись файла.**
  Проходили (проверено `check_policy` с allowlist по умолчанию):
  `git grep -O<prog>`, `git grep --open-files-in-pager=<prog>`,
  `git --config-env=core.fsmonitor=COMSPEC status` (в т.ч. внутри `cmd /c`),
  `git log/diff --output=<любой путь>`, `git --git-dir/--work-tree=<вне workspace>`.
  `--config-env` блокировался на `main` и в #1–#7, а в #8 (`b71f047`) при
  переписывании regex потерялся — регрессия. Всё это теперь блокируется;
  `-O` проверяется с учётом регистра, чтобы не ломать законный `git grep -o`.
- **Allowlist сверялся только с первым словом команды** (с #8). Узкие правила
  вида `^git (status|log)\b` перестали работать вообще (блокировали даже
  `git status`). Теперь шаблон сверяется с началом сегмента (и с head для
  обратной совместимости); подставить команду в середине по-прежнему нельзя.

### 3.2 Корректность — direct / orchestrator
- **Обрыв upstream отдавался клиенту как успешный `stop`** (с #3). `direct`
  выдавал `{"type":"error"}`, но в цикле orchestrator не было ветки `error` →
  `setdefault("reason","stop")`. Клиент получал обрезанный текст или
  Anthropic `tool_use` с неполным JSON. Теперь событие `error` поднимается как
  ошибка хода.
- **Повтор пустого ответа был мёртвым кодом** (найдено при написании тестов).
  1) `produced = True` ставился на любое событие, включая `credits`, а пустой
  ответ upstream — это именно metadata+end_of_stream; 2) даже если повтор
  запускался, он читал сентинел `None` предыдущего воркера из **общей** очереди и
  тут же завершался пустым. Теперь: `credits`/`thinking_heartbeat` не считаются
  выводом, и у каждой попытки своя очередь.
- **`__managed__` не работал, если ресурс задан только в `accounts[]`** (#13):
  глобальный `provider_resource()` до acquire отдавал 503. Теперь до acquire
  проверяется только маршрутизируемость провайдера, ресурс берётся из cfg
  аккаунта; при `__managed__` поле удаляется (не отправляется `null`).
- **Keepwarm (#13 и старше):**
  - `_warm_at` ставился на **конец** хода → после длинного хода и паузы кэш
    истекал до следующего idle-пинга. Теперь якорь — начало хода или последний
    during-turn пинг;
  - пинг во время хода отправлял тело **прошлого** хода, а на первом ходе
    сессии пинга не было вовсе (задача keepwarm создавалась только в `finally`).
    Теперь тело активного хода (`_turn_body`) и запуск планировщика в начале хода;
  - поздний пинг мог пометить уже **следующий** ход как пропингованный — guard
    по `_turn_seq`;
  - `_ping` не проверял error-события → неудачный пинг логировался как
    «TTL продлён». Теперь error-событие = исключение = warn в журнале;
  - счётчик неудач не сбрасывался для новой задачи keepwarm — сброшен;
  - тело, отвергнутое upstream (4xx кроме 401/403/408/429), больше не становится
    телом прогрева.
- **`prefix_tokens` всегда 0:** orchestrator писал `_last_prefix_tokens` на
  `SessionLease` (у неё есть `__getattr__`, но нет `__setattr__`), а keepwarm
  читает настоящую сессию. Теперь пишется в саму сессию.
- **`_bounded_put` молча выбрасывал кадр** после 120 с ожидания (#6) — поток
  уходил клиенту с дырой. Теперь воркер прекращает чтение, и это всплывает как
  ошибка обрыва потока.
- `content_block_end` с неизвестным `toolCallId` закрывал чужой открытый вызов
  (#4) — теперь игнорируется.
- **Учёт кредитов** терял все события, кроме первого, в одном ходе (retry,
  exec-followup): дедуп по `turn_id`. Теперь каждое событие — свой ключ.
