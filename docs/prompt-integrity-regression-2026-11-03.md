# Подмена задачи при восстановлении: разбор и отмена, 3 ноября 2026

## Что произошло

Подход из `ff8e7e4` мог завершить пустой ход обычным текстом, но не обеспечивал
выполнение исходной задачи. Он добавлял требование ответить коротким статусом,
отложить инструменты до следующего хода и менял автоматический выбор инструментов
на `toolChoice=none`. Это ограничивало модель и меняло смысл запроса пользователя.

На скриншоте пользователя показана сессия OpenCode
`ses_e5daa06ecffex3QSeK0mA7dVq2`. Её сообщения и журнал подтверждают:

- `f83004def31c`: три пустых ответа, затем `recovery_mode=text_status`;
  четвёртая попытка выдала обещание найти базу и прочитать размышления;
- `94c76e26c54e`: после «ну давай» повторился тот же сценарий;
- оба хода завершены `stop`, без вызова инструмента для поставленной задачи.

Новый клиентский запрос действительно возвращал `auto`, однако при следующем
пустом ответе восстановление снова запрещало инструменты. Поэтому отсутствие
постоянного `none` в состоянии сессии не исключало повторяющийся тупик.
Прежняя проверка на чтении README была недостаточна для вывода о восстановлении
исходной задачи. Внутренняя ошибка Retool при этом никуда не исчезла.

## Исправлено в relay

1. Полностью удалены текстовое восстановление и принудительный `toolChoice=none`.
2. Direct-повторы используют одинаковый payload, включая все инструкции,
   историю, модель, effort, определения инструментов и выбор инструментов.
   `[RETRY]` и указания перейти к короткому ответу в direct-запрос не добавляются.
3. Пустой или thinking-only ответ повторяется до общего предела **5 POST**.
   После исчерпания бюджета возвращается ошибка. Успешный вызов инструмента
   завершает повторы; обрыв после начала ответа не вызывает опасный повтор.
4. Для direct-запросов с инструментами передаётся сам непустой системный промпт
   клиента. Убраны дополнительные указания relay и блок выбора инструментов,
   который мог противоречить фактически отправленному выбору.
5. Удалена локальная обрезка описаний инструментов до 1000 символов и описаний
   параметров до 500. В снимке сбоя описания `execute` и `subagent` были ровно
   по 1000 символов. Их полнота теперь проверяется отдельной регрессией.
6. Текстовая коррекция вызовов через `<tool_call>` остаётся только для агентского
   WebSocket-транспорта, которому этот мост нужен; direct её не использует.

Настройки SDK, включая явный выбор инструмента и лимиты ответа, сохраняются.
При отсутствии системных инструкций остаётся стандартная роль помощника.
Передача нового system prompt и tool set проверяется на одной и той же
сессии для Chat, Responses и Anthropic. Старый system prompt не заменяет новый
ради кэша. Смена ключа префикса может потребовать платной записи кэша заново.

## Живые проверки и их границы

Исходный снимок:
`logs/upstream-400/20261103-200141-94c76e26c54e-252d86c1199e-body.json`.
Сохранена вся история. Изменялся только system head: из него извлечены
неизменённые инструкции OpenCode без надстройки relay. Модель, effort,
автоматический выбор и захваченные инструменты оставлены прежними.

1. Старый head: HTTP 200, `outputTokens=0`, только metadata/end.
2. Head клиента: два отдельных запроса выдали корректный нативный `shell`
   с валидным JSON для поиска базы OpenCode.
3. Тот же запрос через настоящие `validate`, `TurnRunner`, direct transport и
   Chat adapter текущего checkout: одна попытка, `finish_reason=tool_calls`,
   один корректный `shell`, 0,354496 кредита. Прокси на 8787 не запускался
   и не перезапускался; модель не получала просьбы ответить статусом.
4. Запрошенная read-only команда действительно выполнена: перечислены файлы
   каталога OpenCode и версия SQLite. Её настоящий результат передан дальше
   с полной историей и исходными инструкциями.
5. **Это продолжение снова дало пять пустых ответов**, 1,013432 кредита.
   Клиентский ответ — ошибка; она не подменена обещанием будущей работы.
6. Отдельная проверка той же истории с нативными ролями assistant/tool также
   дала пустой ответ. Это сравнение не устанавливает причинность, и миграция
   всей истории на новый формат не объявляется исправлением данного сбоя.

Успешная выдача первого инструмента не доказывает исправление продолжения.
Источник metadata-only ответов внутри Retool/провайдера остаётся не установленным.
Текущая правка устраняет доказанную локальную регрессию и искажения инструкций,
но не объявляется устранением всех пустых ответов upstream.

Приватные запросы/ответы и результаты сравнения находятся в игнорируемых
`.agents/empty-recovery/` и `.agents/prompt-integrity/`; в Git они не включены.
Работающая копия relay, запущенная пользователем, не перезапускалась: для
загрузки исправления нужен обычный перезапуск пользователем.
