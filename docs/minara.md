# Minara: второй upstream с Bearer-токеном

Minara подключается отдельно от Retool, через OpenAI Chat Completions API.
Можно запустить только Minara или добавить её аккаунт в существующий пул Retool.
Локальный ключ relay и Bearer-токен Minara — **разные секреты**: клиент получает
ключ relay, а токен провайдера остаётся на сервере.

Для общего списка моделей без отдельных слотов используйте `public_id`: см.
[единый пул Retool и Minara](unified-routing.md). Старые namespaced ID остаются
совместимыми, но отображённые модели публикуются под одним привычным именем.

## Настройка

Установите зависимости из `requirements.txt`. HTTP-транспорт Minara использует
`curl_cffi`, `impersonate="chrome131"` и streaming. Перенаправления отключены,
чтобы Bearer-токен не ушёл на адрес из ответа upstream.

Предпочтительно передавать токен через окружение процесса relay:

```powershell
$env:MINARA_TOKEN = '<токен тестового или вашего аккаунта>'
python proxy.py
```

Не сохраняйте эту команду с настоящим токеном в общие скрипты или отчёты.
Переменная должна быть доступна именно процессу relay; уже запущенный процесс
не получает изменения окружения другого терминала.

Минимальная конфигурация только для Minara (вместо Retool-полей конфигурации):

```json
{
  "upstream": "minara",
  "base": "https://api.minara.ai/v1",
  "bearer_token_env": "MINARA_TOKEN",
  "model": "minara/openai/gpt-oss-20b",
  "minara_models": [
    {
      "id": "openai/gpt-oss-20b",
      "tools": true,
      "reasoning": true
    }
  ],
  "host": "127.0.0.1",
  "port": 8787,
  "transport": "direct"
}
```

`base` для аккаунта Minara по умолчанию равен `https://api.minara.ai/v1`.
`cookie`, `xsrf`, `page_uuid` и Retool provider resource UUID не нужны.
Вместо `bearer_token_env` поддерживается `bearer_token` со значением токена,
но переменная окружения предпочтительнее. Не указывайте оба способа сразу.
Не помещайте настоящий токен в `config.example.json`, Git или клиентский конфиг.

В смешанном пуле добавьте в существующий `accounts` **отдельную запись**:

```json
{
  "account_id": "minara-test",
  "label": "Minara",
  "upstream": "minara",
  "base": "https://api.minara.ai/v1",
  "bearer_token_env": "MINARA_TOKEN",
  "minara_models": [
    {"id": "openai/gpt-oss-20b", "tools": true, "reasoning": true}
  ]
}
```

Это фрагмент записи, а не полный файл конфигурации. Сохраните остальные настройки
и записи Retool. Для существующих аккаунтов без `upstream` действует прежнее
значение `retool`. Токен, список моделей и Retool-учётные данные не наследуются
от одного аккаунта другим; настройте их в нужной записи явно.

## Модели и возможности маршрута

`minara_models` — непустой явный список разрешённых моделей аккаунта. Элемент —
строка с upstream ID или объект с полем `id` и необязательными метаданными:

| Поле | Значение |
|---|---|
| `id` | Полный ID Minara, например `openai/gpt-oss-20b`; внутренний `/` сохраняется |
| `label` | Отображаемое имя |
| `provider` | Семейство модели; по умолчанию часть ID до первого `/`, не название upstream |
| `context`, `max_output` | Положительные целые ограничения, только если известны |
| `tools`, `image`, `reasoning` | Явные булевы возможности; по умолчанию `false` |
| `reasoning_effort_levels` | Список поддержанных уровней effort; по умолчанию пустой |

Relay публикует маршрут как `minara/<id>`. Например,
`minara/openai/gpt-oss-20b` в клиентском запросе превращается в
`openai/gpt-oss-20b` в POST к Minara. Retool-модели сохраняют прежние имена.
Неизвестный `minara/...` не должен переключаться на Retool. Если одна модель
настроена на нескольких Minara-аккаунтах, её описания должны совпадать.

Простая строка в списке не означает, что relay проверил tools, изображения или
effort. Неизвестные размеры контекста и ответа остаются неизвестными, а не
копируются из похожей модели Retool. Метаданные описывают настройку оператора,
а не сертификат возможностей провайдера.

Каталог Minara не импортируется автоматически. `GET /v1/models` провайдера
содержит в том числе нечатовые маршруты: не добавляйте image/video-модели только
потому, что их ID есть в этом ответе. Для данного транспорта выбирайте записи,
у которых `supported_endpoint_types` включает `openai`, и проверяйте возможности
каждого нужного маршрута отдельно.

## Проверка клиента

Клиент подключается к прежнему локальному `/v1`, использует **ключ relay** и
выбирает опубликованный Minara ID. Например, после настройки и запуска:

```powershell
$headers = @{ Authorization = "Bearer $env:RELAY_API_KEY" }
$body = @{
  model = 'minara/openai/gpt-oss-20b'
  messages = @(@{ role = 'user'; content = 'Say OK only.' })
  max_tokens = 128
  stream = $false
} | ConvertTo-Json -Depth 8
Invoke-RestMethod 'http://127.0.0.1:8787/v1/chat/completions' `
  -Method Post -Headers $headers -ContentType 'application/json' -Body $body
```

В примере `RELAY_API_KEY` должен содержать фактический локальный ключ relay;
если relay создал `relay_key.txt`, возьмите локальный ключ оттуда. Не подставляйте
в этот запрос токен Minara. Генерация может списать деньги с аккаунта Minara.

## Расходы, состояние и ограничения

- Для Minara нет фонового Retool refresh, Retool balance lookup и keepwarm POST.
  Relay не пытается продлить Bearer-токен через Retool. При истечении или отзыве
  токена обновите учётные данные и перезапустите процесс с актуальным окружением.
- Баланс Minara не проверен через отдельный endpoint. Неизвестный остаток не
  считается нулём и не складывается с кредитами Retool. `usage.cost` upstream
  также нельзя интерпретировать как Retool `credits_used`.
  Сообщённая upstream цена возвращается отдельно как `provider_cost`; валюта
  берётся только из явного поля upstream, иначе `provider_cost_currency: null`.
  `/v1/usage` считает ходы и попытки отдельно. Несколько цен без известной общей
  валюты не суммируются; отдельные снимки сохраняются в `provider_cost_records`.
  Это статистика текущего процесса, не выписка провайдера и не долговечный биллинг.
- Не рассчитывайте на автоматический платный повтор Minara после обрыва или
  неоднозначного результата. Самостоятельный повтор клиента может создать
  второй оплачиваемый запрос.
- Подписанные блоки Retool не являются историей Minara. Продолжение беседы должно
  передавать обычные assistant/tool сообщения, а не чужие непрозрачные подписи.
- Обходы ограничений Retool (например, его forced-tool эмуляция) не доказывают
  необходимость тех же обходов на Minara. Настраивайте только подтверждённые
  возможности маршрута.

### Что проверено непосредственно у Minara

На 8 ноября 2026 года через `curl_cffi` с Chrome 131 fingerprint проверены
авторизованный каталог и два небольших streaming-запроса
`openai/gpt-oss-20b`: текст и принудительный function tool call. Получены HTTP 200,
стандартные SSE `data:` и `[DONE]`, reasoning/content, фрагменты аргументов tools
и финальная usage. Reasoning был продублирован в разных upstream-полях: его нельзя
показывать дважды. Finish chunk может повторяться в usage chunk: окончание ответа
тоже должно быть одно.

Дополнительно отдельный временный HTTP relay проверен живыми небольшими запросами:
Chat Completions, Responses и Messages, streaming/non-streaming, а также
function call и успешное продолжение с его результатом. Рабочий relay и его
конфигурация при этих проверках не менялись.

Установленные Claude Code 2.1.310 и OpenCode 1.19.3 прошли чтение временного
файла инструментом и передачу результата обратно через relay с подменённым
upstream. Codex CLI 0.167.0 прошёл текстовый запрос с `web_search="disabled"`;
его встроенный `web_search` по умолчанию пока отклоняется существующим контрактом
relay. Эти проверки клиентов не являются live-проверкой их запросов на Minara.

После исправления visual tool-result Codex прошёл настоящий `view_image` и
передачу изображения в следующий запрос (синтетический upstream). Harness также
прошёл настоящий read-only tool roundtrip. Дополнительно Claude Code проверен
уже с живой Minara: модель вызвала `Read` и вернула уникальное содержимое файла.
Команды, результаты, этапы независимых проверок и границы доказательств —
[в итоговом отчёте](reports/minara-integration-2026-11-08.md).

Эти запросы подтверждают указанные случаи на указанной модели, **не** весь каталог,
не все уровни effort, не поддержку изображений и не сквозную совместимость каждого
клиента relay. Расценки из каталога могут быть выражениями с тарифными ступенями;
их нельзя выполнять как код или выдавать за проверенную плоскую цену.
